# 平台开发智能体v2.6 完整交互接口汇总
分为两大体系：**内部AgentMessage消息接口（多智能体协同）**、**对外RESTful HTTP接口（设备/算法/运维/前端）**，统一标注接口名称、流向、入参、出参、数据格式。
## 一、内部统一基础规范
1. 消息载体：所有智能体互通外层固定为**JSON序列化AgentMessage结构体**
2. 身份标识：sender固定=platform；接收方receiver：algorithm/arch/pm/ceo
3. 通用消息固定字段（全局统一入参结构）
```json
{
  "sender": "string", // 固定platform
  "receiver": "string", // 目标智能体标识
  "task_type": "string", // 业务动作标识
  "msg_id": "string", // 全局唯一幂等ID
  "reply_to": "string|null", // 应答关联原消息ID
  "status": "enum", // pending/processing/done/error
  "timeout": "int", // 默认60000ms
  "attach": "object", // 业务载荷（核心入参/结果）
  "error_code": "int|null",
  "error_msg": "string|null"
}
```
4. 文件传输规则：attach内仅传递`file_path(绝对路径string)`+`md5(string)`，不传输二进制；文件后缀规范：`.json`结构化数据、`.md`文档报告、`.yaml`工程配置
5. 鉴权：HMAC-SHA256全局签名

## 第一部分：内部AgentMessage业务接口（智能体之间）
### 1. 对接算法工程师 algorithm
#### （1）task_type: model_receive 接收模型交付（算法→平台）
- 流向：algorithm → platform
- attach入参（算法推送）
```json
{
  "model_file": {"file_path":"string","md5":"string"}, // ONNX模型
  "config_yaml": {"file_path":"string","md5":"string"}, // 推理配置
  "dataset_info": {"json结构化数据集参数"}
}
```
- 平台应答status=done/error；attach出参
```json
{
  "integrate_check": "bool", // 集成校验是否通过
  "test_metrics": {"accuracy":"float","infer_ms":"float","fps":"float"}, // JSON指标
  "log_file": {"file_path":"string","md5":"string"}
}
```

#### （2）task_type: model_feedback 测试结果反馈（平台→algorithm）
- 流向：platform → algorithm
- attach入参：同上应答metrics结构
- 算法应答仅回ack状态

### 2. 对接系统架构师 arch
#### （1）task_type: arch_spec_receive 接收架构约束（arch→platform）
- 流向：arch → platform
- attach入参
```json
{
  "adr_doc": {"file_path":"string","md5":"string"}, // Markdown ADR架构文档
  "tech_constraint": {"json结构：算力上限、端口、部署规则、依赖版本"}
}
```
#### （2）task_type: arch_self_check 平台架构适配自检反馈（platform→arch）
- 流向：platform → arch
- attach出参
```json
{
  "match_status": "bool",
  "conflict_list": ["string冲突项数组"],
  "adjust_suggest": {"file_path":"string","md5":"string"} // md调整说明文档
}
```

### 3. 对接产品经理 pm（全链路枢纽）
#### （1）task_type: prd_receive 接收需求PRD（pm→platform）
- 流向：pm → platform
- attach入参
```json
{
  "prd_md": {"file_path":"string","md5":"string"}, // Markdown需求文档
  "require_json": {"需求点、交付周期、验收阈值结构化json"}
}
```
#### （2）task_type: progress_report 进度上报（platform→pm）
- 流向：platform → pm
- attach出参
```json
{
  "progress_pct": "float",
  "stage": "string", // 集成/联调/上线
  "risk_items": ["string风险数组"],
  "accept_report": {"file_path":"string","md5":"string"} // md验收报告
}
```
#### （3）task_type: task_assign 任务下发（pm→platform）
入参：attach携带拆解后的工程任务JSON配置；平台应答执行状态

### 4. 对接CEO顶层调度
#### task_type: ceo_task 顶层任务指令（ceo→platform）
入参attach：全局调度JSON参数；平台attach出参：顶层汇总进度JSON+md总报告路径

### 通用内部公共消息接口
1. task_type: heartbeat 心跳保活：入参空attach，出参在线状态bool
2. task_type: fault_alert 故障上报：attach携带故障code、描述、日志路径
3. task_type: ack_reply 通用应答回执：仅回status状态，极简载荷

## 第二部分：对外RESTful HTTP接口（JSON请求/响应，标准REST）
基础前缀：`/api/v1/`；智能体专属路由前缀：`/agent/api/`
通用HTTP响应固定格式（所有接口统一出参结构）
```json
{
  "code": 200/400/404/429/500, // 状态码
  "msg": "string描述",
  "data": "object|null" // 业务载荷
}
```
鉴权：设备Token/JWT；算法专属HTTP附加内部密钥鉴权

### 一、智能体专属HTTP接口（仅对内智能体调用）
#### 1. 算法工程师专属对接
1. POST `/agent/api/alg/deliver_model`
   - 请求体：multipart/form-data
     - file：onnx模型二进制文件
     - config：yaml配置文本字符串
     - device_id：string
   - 响应data：校验结果JSON（同AgentMessage test_metrics结构）
2. POST `/agent/api/platform/model_test`
   - 请求JSON入参：模型标识、测试样本参数
   - 响应data：完整测试指标JSON

#### 2. 架构师对接
1. POST `/agent/api/arch/deliver_spec`
   - JSON入参：adr文档文本、约束json
   - 响应data：接收确认bool
2. POST `/agent/api/platform/arch_check`
   - 响应data：适配自检结果JSON

#### 3. 产品经理对接
1. POST `/agent/api/pm/deliver_prd`
   - JSON入参：prd md文本、结构化需求json
2. POST `/agent/api/platform/feedback_require`
   - JSON入参：疑问、进度数据

### 二、对外业务核心HTTP接口（工地设备/前端）
1. POST `/api/v1/detect/image` 图片检测
   - 请求：multipart/form-data
     - file：图片二进制
     - device_id: string
     - timestamp: long毫秒
   - 响应data：检测框数组、置信度、推理耗时float
2. POST `/api/v1/detect/video` 视频流检测
   - 入参：视频流地址、通道数int；出参：实时帧告警JSON数组
3. GET `/api/v1/records` 历史检测记录
   - Query入参：device_id、start_time、end_time；出参：分页记录JSON列表
4. GET/POST `/api/v1/alarms` 告警查询/配置
   - POST入参：告警阈值JSON；GET出参：告警列表JSON

### 三、管理员运维HTTP接口
1. 用户管理：`/api/v1/admin/users` CRUD JSON入出参
2. 模型热重载：POST `/api/v1/admin/model/reload` 入参model_id:string
3. 设备注册审批：`/api/v1/devices/register`、`/api/v1/devices/approve`
4. 系统配置：POST `/api/v1/admin/system/config` 入参全局配置JSON

### 四、异步RabbitMQ消息（配套HTTP业务）
- 队列名：helmet_alarms（告警推送）、dlx_queue死信队列
- MQ消息体格式：纯JSON，结构对齐HTTP响应data字段，无外层包装

## 三、入参出参数据类型&格式总对照表
| 数据场景 | 存储/传输格式 | 使用位置 | 接收方能否直读、无需转换 |
|----|----|----|----|
| AgentMessage外层包裹 | JSON | 所有智能体互通消息外壳 | 全员统一解析，零转换 |
| 实时数值、状态、指标、配置参数 | JSON | attach结构化载荷、HTTP请求响应data | 算法/架构/产品全部原生解析 |
| 长篇方案、验收、ADR、部署说明文档 | Markdown(.md)文件 | attach携带文件路径+md5 | 和其他智能体md标准完全一致，直接读取 |
| 推理、工程部署配置文件 | YAML(.yaml)文件 | 算法交付、架构约束配置 | 算法原生加载，架构/平台可解析 |
| 二进制文件（模型/图片/视频） | 二进制form-data/本地磁盘文件 | HTTP上传、本地存储 | 平台原生读写解析 |

## 四、关键区分总结
1. 给别的智能体传递**实时机器可读数据**：用内嵌JSON，对方直接解析使用
2. 给别的智能体传递**长篇文档报告**：传递md文件路径，文档格式和架构/产品输出md完全统一
3. 消息外壳永远全团队统一JSON，不存在md包裹消息的情况；md只作为独立附件文件存在
4. HTTP全链路固定JSON响应，form-data仅用来传大二进制文件（模型、图片）
5. 无任何私有自定义格式，全部遵循五大智能体统一规范，对接无格式断层
